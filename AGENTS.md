# AGENTS.md -- magma-themes

## Project type

Data plus generators. JSON theme sources in `themes/`, a zero-dependency node
build in `tools/`, committed outputs in `dist/`. Created 2026-10-17, seeded
from `web/website` `arcade/admin/themes.json` at website `829dd36e`.

## The one rule: edit themes/, never dist/

Everything in `dist/` is generated by `tools/build.mjs` and says so in its
first line. After any edit to `themes/`, run the build and commit both halves
in the same commit. CI runs `node tools/build.mjs --check` and fails on a
stale `dist/`.

```bash
node tools/build.mjs
node --test tests/themes.test.mjs
```

The test suite also checks that every `_TV` macro really is TV safe and that
a safe colour never moves.

## This repo is the source now, not the website

`tools/import-website.mjs` seeded `themes/` once. It refuses to run over an
existing `themes/` without `--force`, because a second import would overwrite
edits made here. Do not use it as a sync.

**The website has not been rewired yet.** As of creation it still owns its
own `arcade/admin/themes.json` and the theme manager writes to that. Until the
site takes `dist/themes.json` from here, the two can drift: an edit in the
theme manager does not reach this repo, and an edit here does not reach the
site. `dist/themes.json` round-trips the site's file exactly, so
`cmp dist/themes.json <website>/arcade/admin/themes.json` is the drift check.

## Roles are guesses until marked "hand"

`"rolesFrom": "import-heuristic"` on a theme means nobody has checked its
roles. Some are plainly off: several George Boole themes have `text` mapped
to `accent` because their palettes have no separate text colour. Fix a theme's
roles by editing its JSON and set `rolesFrom` to `"hand"`.

## Consumers find it the way games find magnolia

`$MAGMA_THEMES`, then `../magma-themes`, then `../../libs/magma-themes`.
A Makefile wants the `dist/` directory on its include path. The repo is
PUBLIC so a public game's CI can check it out with the default token and no
deploy key.
